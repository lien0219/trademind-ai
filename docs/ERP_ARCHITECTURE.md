# ERP 扩展架构

TradeMind 在保留 AI 商品运营和现有多平台协同能力的基础上，采用按业务闭环逐步进入完整 ERP 的路线。ERP 扩展不是一次性重写；每个阶段都必须具备租户隔离、权限、审计、事务、幂等、契约与可回归验证，然后才开放管理端入口。

## 当前已实现范围

当前阶段提供采购入库、采购退货、销售售后基础闭环和受控管理工作台：

- 仓库主数据：租户级仓库编码、启用状态和默认仓库标记。
- 供应商主数据：供应商资料与本地 SKU 的供应商货号、采购价、币种、起订量和交期绑定。
- 采购订单：草稿、待审批、已审批、部分收货、全部收货、关闭、取消状态。
- 分批收货：按采购单明细多次收货，禁止超收；同一幂等键重复提交返回原收货结果，不重复加库存。
- 仓库库存中心：仓库 SKU 余额和不可变库存流水是物理库存事实；Admin 可按全部仓库或单仓查看在手、预占、残次、在途、可售和可用库存，并同时查看兼容投影对账状态。
- 现有 Admin 人工调库入口统一：库存调整必须选择启用仓库，使用调用方幂等键，并在单事务内更新仓库余额、不可变流水、兼容变更日志和 `product_skus.stock` 兼容聚合字段。
- 历史库存迁移与对账：未建立仓库余额的历史规格分批迁入默认仓；没有默认仓时进入租户级“待分配仓”。Admin 可查看一致、待迁移和不一致状态，迁移接口可重复执行且单批有上限。
- SKU 元数据边界：通用 SKU 创建和更新接口不接受库存数量；手工新建和采集导入 SKU 的兼容投影均从 `0` 开始，采集来源库存仅保留在原始 SKU 元数据中，后续库存变化必须进入仓库感知路径。
- 订单库存生命周期：已支付/处理中订单预占仓库 `reserved`，不改 `product_skus.stock`；已发货/已履约订单扣减 `on_hand` 并同步兼容聚合；发货前取消释放预占，已出库退款/取消回补在手库存。每次变化写入租户级、仓库级 `OrderInventoryEffect` 和不可变 `InventoryMovement`，不支持跨仓拆单。
- 履约分仓工作台 V1：对已付款、未履约订单按整单 SKU 需求计算单仓候选；只读推荐规则以整单可满足、默认仓优先和仓库编码稳定排序生成候选排名与操作员可见理由。候选查询只读且不补造库存余额；人工确认以 revision 和调用方幂等键绑定订单、仓库、明细、余额版本与兼容投影，在同一事务完成订单仓绑定和全部明细预占。SKU 未绑定、账本投影不一致、部分历史 effect、库存不足或并发变化均失败关闭。
- 拣货波次与打包复核 V1：人工从同仓、已付款、已整单预占的订单创建持久化波次，冻结订单与规格快照，按 revision 和动作幂等键执行开始拣货、数量/缺货登记、逐单打包和明确完成。缺货订单不能打包；完成只逐单复用本地单仓履约事务，部分失败持久化后等待人工处理，不自动重试。活动波次会阻止单单和旧批量接口绕过仓内流程；取消波次只释放活动归属，不自动释放订单预占。
- 仓内作业 V2 最小闭环：增加租户级仓库库位、单仓 SKU 条码/库位绑定，波次行在创建时冻结绑定快照；拣货确认按条码/库位校验。新建波次在打包前还必须扫描冻结订单号、逐件商品条码和面单条码，可选记录整数克称重；服务端在单事务复核完整行数量、面单与运单一致性、revision 和幂等键，并追加不可变复核/逐行扫描事实。历史波次保留旧人工打包入口且不回填；两类流程均不自动分仓、不接真实物流/平台、不启动 Worker。
- 本地运费试算 V1：租户可维护物流渠道和按仓库、目的国家/区域/邮编前缀、重量区间匹配的运费模板；金额全部使用整数最小货币单位，基础费覆盖起始重量，超出部分按每个起始千克计费。扫描工作台只在操作员显式点击后试算，不自动选择最低价；人工确认同时校验波次 revision、模板 revision 和幂等键，并冻结目的地、渠道、模板、重量、金额与计算说明。确认后重量或承运商变化会阻断打包并要求重新试算。该报价仅为本地规则结果，不代表承运商报价，不申请运单或面单。
- 单订单单仓履约 V1：已支付且所有订单明细完成本地 SKU 绑定后，由人工提交承运商和运单号；实际库存扣减、发货单、订单 `shipped` / `fulfilled` 生命周期和调用方幂等记录在同一事务提交。同一幂等键支持安全重放，不调用真实物流平台、不启动 Worker 或自动重试。
- 订单履约成本快照 V1：成功履约时按订单明细冻结数量、订单/成本币种、唯一有效供应商与供应商 SKU、目录来源时间、采集时间和候选来源审计事实，并与库存扣减、发货单、订单状态及履约幂等在同一事务提交。成本缺失、多绑定、币种不一致或金额无效只形成明确的 `missing` / `ambiguous` / `currency_mismatch` / `invalid` 快照，不阻断发货；快照无法持久化时履约整笔回滚。历史已履约订单不使用当前采购价回填。
- 旧批量履约兼容：后端保留原顺序批量接口供兼容调用，但 Admin 主流程已替换为持久化波次；存在活动波次的订单不能经单单或旧批量接口直接履约。
- 订单仓库绑定：手工订单在首次应用库存时必须指定启用仓；平台订单首次处理绑定租户启用的默认仓。已有成功库存 effect 的订单不可改仓，平台同步会保留已锁定订单行的 ID 与数量，避免预占和后续出库失配。取消释放和退款回补按整单单事务执行，多明细任一行失败时整单回滚。
- 职责分离：operator 可维护采购单并收货，reviewer 可审批但不能编辑或收货，readonly 只能查看。
- Admin 工作台：仓库、供应商采购信息、采购单创建、详情、提交、审批、关闭、取消和分批收货；支持五档响应式、明确错误/空/只读状态和非 GET 请求拦截回归。
- 仓库调拨：单租户单仓到单仓调拨单支持草稿、提交、审批、发出、在途收货和发出前取消；发出/收货事务更新仓库余额、在途数量和不可变库存流水，动作使用 revision 与幂等键保护；Admin 调拨入口位于库存菜单，第一版每个 SKU 仅允许一条明细。
- 库存盘点：按仓库创建盘点快照，逐项录入在手实盘数量，经过提交、审核后过账差异；过账校验仓库余额版本及在手/预占/在途/残损快照，事务内写仓库余额、不可变流水、兼容聚合库存和变更日志，支持动作与明细写入幂等。
- 采购退货：从原收货明细创建退货草稿，所有未取消退货单共同占用可退数量；经提交和独立审批后，由与审批人不同的执行岗完成退货。完成动作在单事务扣减仓库可用库存、写不可变流水、兼容聚合投影和变更日志，库存不足时整笔回滚；本增量不包含供应商退款或财务结算。
- 补货建议到采购草稿：采购菜单下按目标仓库查询安全库存缺口，聚合可用量、在途调拨、未收采购以及供应商的起订量、采购价和交期；全局兼容投影按仓库可售合计（在手减残次）对账，库存账未迁移/不一致或无供应商时失败关闭。具备采购管理权限的用户可选择建议、明确选择共同供应商和数量后创建一张本地采购草稿；服务端以建议哈希重新校验库存和供应商快照并复用既有采购单事务。草稿不会自动提交、审批、收货，不启动 Worker，不调用供应商或真实平台。
- 销售售后：从成功订单扣减事实发起订单明细级 `refund_only` 或 `return_refund`，所有未取消售后单共同占用累计可退数量。仅退款完成不写库存；退货退款由与审批人不同的账号收货到原订单仓，良品增加可售投影，残次品同时增加 `on_hand` 与 `damaged`，可售量不变。售后 `completed` 只表示本地售后流程完成，不等于资金退款成功。
- 退款执行：每个已完成售后最多创建一个独立退款执行单，金额和币种从售后事实复制。操作员可登记外部退款结果，或用已安全关联且金额、币种、类型一致的只读平台终态确认；执行状态、revision、幂等请求 hash、租户内外部退款编号唯一约束和不可变事件共同保护资金事实。该能力不调用真实支付或平台写接口。
- 平台结算账单导入与订单费用对账 V1：操作员在店铺 operate/manage 范围内上传本地 CSV，先经零写入预览，再以文件 SHA-256 和稳定幂等键明确确认。导入批次和交易为不可变事实，租户/店铺/平台/外部交易号防止重复计费；调整与冲正只能追加新交易。对账按订单聚合全部交易并输出 `matched` / `pending` / `mismatch` / `blocked`，支持详情与最多 5000 组的防公式注入 CSV 导出。该能力不连接真实平台、支付或银行，不自动修复、付款或生成会计凭证。
- 仓库操作费台账 V1：租户按仓库维护版本化费率卡，覆盖每单出库基础费、每件拣货费和每包裹打包费。只有已完成履约且已形成打包扫描复核事实的订单进入候选；预览数据库零写入，明确确认同时校验费率 revision、波次 revision、计算 hash、订单唯一性、稳定幂等键和店铺 operate/manage 范围，并保存不可变订单费用快照。后续更正只能追加有符号调整或对原调整做一次性冲正，净额不得为负；幂等重放也重新校验店铺范围。该能力不回填历史订单，不计算每日仓储租金，不接 WMS/仓储商，不自动登记、分摊、换汇、付款、生成应付或凭证。
- 订单预估利润与费用缺口 V4：按租户和授权店铺只读汇总订单 decimal 收入、商品成本、唯一活动波次的最新已确认本地运费、账实一致的成功退款、对账状态为 `matched` 的不可变平台结算费用，以及结构有效、币种一致的已确认仓库操作费净额。已履约订单只读取不可变履约成本快照；历史快照缺失时保持 `pending`，不读取今天的采购价。未履约订单才读取当前唯一有效供应商采购价并标记为估算。金额精确转换为 JavaScript 安全范围内的整数最小货币单位；两种成本都不声明为会计实际成本，未匹配的平台费及缺失/异常费用保持 `null`，只展示已知贡献额，不伪造完整利润。派生状态筛选和 CSV 导出限定最多 5000 单，CSV 防公式注入；广告费用仍缺失，该能力不落库利润、自动换汇、自动分摊、执行真实结算、平台写入或启动 Worker。

本阶段仍不启用真实平台库存写入、真实物流下单、承运商实时报价或物流状态轮询，不启动新增 Worker，也不自动分仓、自动选择物流渠道、自动释放预占或自动重试失败波次。库存中心已以分仓余额展示物理库存事实，但历史未迁移或投影不一致的规格会明确标记并失败关闭，不自动修复。仓库、物流渠道、运费模板与供应商编码创建后保持不可变，状态和业务资料通过租户级管理 API 更新；供应商联系方式继续按 `pii.read_full` 权限脱敏。

## 模块边界

| 模块 | 职责 | 允许依赖 |
| --- | --- | --- |
| `warehouse` | 仓库主数据与有效性校验 | shared/database |
| `logistics` | 本地物流渠道、运费模板与确定性只读试算 | warehouse 只读校验、shared/database |
| `supplier` | 供应商及供应商 SKU 绑定 | product、shared/database |
| `procurement` | 采购单与采购退货状态机、审批、收货/退货事务与幂等 | warehouse/supplier 的校验接口、inventory 收货/退货接口 |
| `salesreturn` | 销售售后状态机、原扣减额度、审批/收货分权、售后库存 effect、退款执行和平台资金事实复核 | order 只读事实、warehouse 校验接口、inventory 销售退货收货接口、平台售后只读事实 |
| `inventory` | 仓库余额、可用/可售读模型、库存流水和兼容投影写入与对账 | product、warehouse、shared/database |
| `order` | 订单生命周期、仓内履约编排和不可变订单项成本快照 | inventory 事务接口、supplier 成本只读契约、warehouse/logistics、shared/database |
| `settlement` | 本地账单预览、不可变平台结算交易与订单费用对账 | shop/order 只读事实、shared/database |
| `warehousefee` | 版本化仓库操作费率、零写入预览、不可变订单费用快照和追加式调整/冲正 | order 导出的已履约/打包复核只读事实、warehouse 有效性校验、shared/database |
| `profitability` | 订单级预估利润、已知贡献额和费用缺口只读投影 | order 的履约成本快照、未履约 supplier 目录估算、logistics、salesreturn 的只读事实，以及 settlement/warehousefee 导出的有效费用读取契约 |

HTTP handler 只负责参数、权限和响应；业务状态与事务由 service 管理。采购与销售售后模块不直接修改 SKU 库存表，而是调用 inventory 的事务内收货/退货契约。

## 核心数据约束

- 所有业务行必须带 `tenant_id`，读取和写入同时限定租户。
- 金额使用整数最小货币单位字段 `*_minor`，不使用浮点数做采购金额计算。
- 采购单以 `revision` 做乐观并发控制，状态写请求必须提交 `expectedRevision`。
- 采购单创建幂等范围为 `tenant_id + idempotency_key`，收货幂等范围为 `tenant_id + purchase_order_id + idempotency_key`；同键不同 payload 固定返回冲突。
- 收货单、收货明细、采购明细累计数量、仓库余额、库存流水、兼容库存和变更日志在同一数据库事务提交。
- 订单取消释放、退款回补的订单明细、仓库余额、库存 effect、库存流水、兼容库存和变更日志必须在同一事务提交或全部回滚；多明细锁按确定性 SKU 顺序执行。
- 采购退货创建幂等范围为 `tenant_id + idempotency_key`；每个状态动作提交独立稳定幂等键和 `expectedRevision`。原收货明细在创建事务中锁定，未取消退货数量不能超过该明细已收数量。
- 采购退货完成必须校验仓库 `on_hand - reserved - damaged` 可用量；退货状态、仓库余额、库存流水、兼容聚合和变更日志必须全部提交或全部回滚。
- 销售售后创建幂等范围为 `tenant_id + idempotency_key`；每个动作提交独立稳定幂等键和 `expectedRevision`。有效售后累计数量不能超过成功扣减数量减去整单回补数量；已取消售后释放占用。
- `refund_only` 完成只写状态与 action 审计事实。`return_refund` 完成必须把售后状态、原订单仓余额、独立 `sales_return_inventory_effects`、库存流水、兼容投影和变更日志全部提交或全部回滚；审批人不得收货自己审批的售后单。
- 退款执行创建幂等范围为 `tenant_id + idempotency_key`，同一 `sales_return_id` 只能有一个执行单；非空外部退款编号在租户内唯一。结果动作必须提交 `expectedRevision` 和独立幂等键，变更与不可变 `refund_execution_events` 在同一事务提交。
- 退款金额、币种、订单和店铺范围只能从已完成售后及原订单复制；审批人不得登记或按平台事实确认自己审批的退款结果。平台确认只接受安全关联、账实字段一致且已终结的只读事实。
- `inventory_movements` 是不可变业务事实；重复业务事件由 `business_event_key` 唯一约束拦截。
- `order_item_cost_snapshots` 以 `tenant_id + order_id + order_item_id` 唯一；每个成功履约明细必须在同一事务形成一条已解析或未解析事实。已履约历史订单不自动补造，利润读取不得回退当前目录价。
- 仓库操作费率卡以 `tenant_id + warehouse_id + code` 唯一，每次修订追加 `tenant_id + rate_card_id + revision` 唯一历史；确认快照以 `tenant_id + order_id` 和 `tenant_id + idempotency_key` 双重唯一。
- 仓库操作费调整以 `tenant_id + idempotency_key` 唯一；冲正必须引用同一快照的原调整，`reverses_adjustment_id` 唯一，防止二次冲正。利润读取会重新验证快照金额分解、调整类型、币种和冲正引用，异常事实失败关闭。
- 采购单审批与执行分权，成功状态变更写入统一操作日志。

## 库存兼容迁移

`product_skus.stock` 已明确降级为全局兼容可售投影，不再作为可用库存事实。全局可售为各仓 `max(on_hand - damaged, 0)` 之和；单仓/全局可用为各仓 `max(on_hand - reserved - damaged, 0)` 之和。采购收货与退货、销售退货良品收货、人工调库、盘点差异过账以及订单实际出库/退款回补在同一事务更新仓库余额、不可变流水、兼容变更日志和该投影；销售退货残次品收货只增加仓库 `on_hand` 与 `damaged`，兼容可售投影增量为 `0`。订单预占只增加仓库 `reserved`，不提前扣减兼容投影。首次为已有 SKU 建立仓库余额时，会把当时的旧投影记录为明确的 `legacy_import` 期初事实。手工新建与采集导入 SKU 从零投影开始；采集来源库存只保留为原始元数据，不进入 ERP 库存。

所有本地库存事务对兼容投影的写入统一经过 `inventory` 模块的投影写入边界，并同时校验 SKU 与商品归属；投影更新目标不存在或归属不一致时整笔事务失败关闭。平台库存同步只更新平台发布 SKU 快照，不得直接写入本地 `product_skus.stock`。

订单生命周期已进入仓库账，但当前仍限定为单订单单仓，不支持跨仓拆单。分仓工作台只提供可解释的只读推荐、人工确认和已分仓批量履约，不提供自动分仓执行、批量自动分配或跨仓拆单；候选 revision 过期必须刷新，不允许静默沿用旧库存快照。库存 effect 建立后不得修改或删除订单明细，未释放/回补前不得删除订单。订单同步和库存同步仍受既有租户、权限、幂等和平台 fail-closed 保护，`syncInventory` 不等于已向真实平台写入。

## 状态机

```text
draft -> pending_approval -> approved -> partially_received -> received
  |             |              |                 |
  +---------- cancelled -------+                 +-> closed
                               +--------------------> closed
```

- `draft` 只能提交或取消。
- `pending_approval` 只能审批或取消。
- `approved` 可收货、关闭或在尚未收货时取消。
- `partially_received` 可继续收货或关闭，不允许取消。
- `received`、`closed`、`cancelled` 为本阶段终态。

仓库调拨使用独立状态机：

```text
draft -> pending_approval -> approved -> in_transit -> received
  |             |              |
  +-------------+--------------> cancelled
```

- 调拨创建使用租户级 `idempotencyKey`；提交、审批、发出、收货和取消各自使用 action 幂等键。
- 所有动作提交 `expectedRevision`；发出后禁止取消，收货只允许启用目标仓。
- 调拨不改变 `product_skus.stock` 聚合值，不调用真实平台库存接口。

采购退货使用独立状态机：

```text
draft -> pending_approval -> approved -> completed
  |             |              |
  +-------------+--------------> cancelled
```

- 创建、提交、审批、执行和取消均受租户、权限、revision 与幂等保护。
- `completed` 为不可变终态；审批人不得执行同一退货单。
- 退货只处理库存事实，不触发真实平台同步、供应商退款或财务结算。

销售售后使用独立状态机：

```text
draft -> pending_approval -> approved -> completed
  |             |              |
  +-------------+--------------> cancelled
```

- 创建、提交、审批、完成和取消均受租户、权限、revision 与 action 幂等保护。
- `refund_only` 和 `return_refund` 都占用原订单明细的成功扣减数量；取消释放占用，完成后不可取消。
- `return_refund` 的审批人与收货人必须不同；`refund_only` 也沿用审批/完成人分离，且完成时不写任何库存事实。
- 不调用支付 Provider 或真实平台售后接口，不支持换货、自动重试或新增 Worker。

退款执行使用独立状态机：

```text
pending -> succeeded | failed | unknown | cancelled
                              |
                              +-> succeeded | failed  (仅由匹配的平台终态确认)
```

- 仅已完成售后可创建退款执行单；售后完成与资金结果分别展示和审计。
- `manual` 来源记录人工在外部渠道完成的结果，`platform_fact` 来源仅根据只读平台事实确认，不产生外部写请求。
- `succeeded`、`failed`、`cancelled` 为本地终态；`unknown` 只允许后续用匹配的平台终态收敛。

## 当前非目标

- 不默认引入微服务、Kafka、Kubernetes 或独立 WMS。
- 不自动向真实店铺推送库存，不自动采购或自动补货。
- 不调用真实支付退款或平台售后接口，不自动换货或重试。
- 不调用真实平台结算、支付或银行接口，不自动修复账单差异、付款或生成会计凭证。
- 不接真实 WMS/仓储服务商，不自动登记仓库操作费，不计算每日仓储租金，不生成应付或会计凭证。
- 不申请真实运单号，不把本地包裹标签描述为承运商官方面单，不控制物理打印机或声明打印成功。
- 不在 HTTP 请求中调用长耗时第三方流程。
- 不把代码完成等同于生产可用；PostgreSQL/Redis、部署、监控、备份恢复和人工业务验收仍需独立证明。
