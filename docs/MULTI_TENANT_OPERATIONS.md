# TradeMind 多租户运维手册

更新时间：2026-10-25。适用于受控运维与预生产准备，不代表已经执行生产变更。数据库迁移程序见[迁移手册](MULTI_TENANT_MIGRATION.md)，人工签收见[验收清单](MULTI_TENANT_ACCEPTANCE.md)。

## 平台运营者管理

平台运营者是 `platform_operators` 中独立的已启用身份。应用没有授予/撤销此权限的 API 或 UI；租户角色、旧全局 admin 角色和 tenant 0 均不能替代平台运营者授权。

新增/撤销前应确认申请人身份、职责、有效期与替补运营者，获得两人复核，在受控数据库访问渠道执行最小化变更，并记录申请号、操作者、复核者、目标 `user_id`、生效/撤销时间和变更结果。通过数据库审计记录实际 SQL 身份与事务；变更后以目标身份验证平台租户控制面，同时确认其没有被自动加入任何客户 tenant。无业务需要时撤销授权。应用的租户审计页不能代替数据库操作审计。

## 租户开通

1. 仅具备独立平台运营者授权的身份可调用 `POST /api/v1/platform/tenants`。
2. 提供唯一 code、企业名称、owner 邮箱和稳定幂等键。首次 owner 账户需符合现有密码策略并在首次登录时改密；已存在 owner 身份必须 active，并继续使用原身份。
3. 服务事务创建/复用 owner、管理员 membership、租户和成功审计。创建不授予平台运营者租户成员身份以外的业务权限；需要进入业务时应使用真实 tenant admin 身份。
4. 重试必须复用相同幂等键和相同业务参数。键相同但请求摘要不同会冲突；不得用新键掩盖结果未知。
5. 管理台只显示已认证调用可访问的结果；邀请创建不自动发送邮件，须通过受控渠道把一次性 Token 交给目标邮箱用户。

## 成员和邀请

租户管理员在当前 tenant context 下管理成员、角色及店铺 view/operate 权限。提交前核对店铺确实属于该 tenant。邀请接受要求当前登录身份的邮箱与邀请匹配，且邀请未过期、未取消、未使用；成员页面应确认最后一名有效管理员保护和既有身份复用。

权限或状态变更后，要求成员刷新/重新登录；服务端会撤销相关会话。成员无法离开或被降权为 tenant 内没有有效管理员的状态。平台支持工单或人工联系管理员，不通过公开注册重建绕过邀请。

## 暂停、恢复和归档

状态更新需要提供当前 `version`，并按合法状态迁移执行。暂停会拒绝正常 tenant 访问并撤销当前成员会话凭据；恢复后成员需重新认证。归档/关闭不做物理删除且为终态，不可经当前 API 重新打开。任何停用前先确认后台任务、店铺授权、财务/审计保留义务及客户通知；该实现不会自动删除历史数据，也不会替代完整租户关闭/数据保留流程。

## 审计、告警和事件响应

平台租户列表/详情/审计端点需平台运营者。租户内操作审计按 tenant ID 查询。审计事件 `tenant.create`、`tenant.update`、`tenant.status.update`、`tenant.membership.update`、`tenant.membership.leave`、`tenant.invitation.create`、`tenant.invitation.accept`、`tenant.invitation.cancel` 用于调查；平台运营者的直接数据库变更则查询数据库审计和变更单。

若怀疑跨租户读取：保留请求 ID、租户、用户、Session、资源和时间窗；先撤销受影响用户 Session/Refresh，必要时通过已审批的租户暂停入口阻止进一步访问；冻结相关任务、文件和审计数据；按同一攻击路径检查读取、导出、Worker 和 Webhook；完成影响评估和恢复演练后再恢复服务。避免在日志或工单复制凭据、Token、客户数据正文。

## 生产启用边界

生产启用前仍需：完整安全扫描及处置、跨租户攻击矩阵和人工验收、数据库备份恢复演练、生产规模锁/索引耗时评估、平台运营者双人授权流程验证、最终 SHA 的远程 CI，以及应用/对象存储/Redis 与任务通路的完整盘点。详见[状态表](MULTI_TENANT_ACCEPTANCE.md)。
