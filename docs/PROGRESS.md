# TradeMind 当前维护状态

更新时间：2026-08-21

## 生命周期

TradeMind 已由项目所有者确认进入生产维护阶段。当前工作重点是稳定性、安全修复、必要功能维护和简洁的生产文档，不再在工作树中累积阶段性开发报告、一次性验收门禁或本地运行证据。

“生产维护阶段”描述项目生命周期，不代表仓库可以自动启用真实平台能力。仓库默认仍为 `L0`，真实凭据、真实平台网络、抖店草稿写、后台 Worker 和灰度均关闭，库存写入与自动业务重试继续禁止。代码具备候选能力不等于部署或上线；CI、独立预生产、真实平台验收、备份恢复/回滚和发布审批仍是外部前置。

## AI 客服生产加固

2026-08-12 修复客服人工外发缺失 `clientMessageId` 导致请求不符合后端幂等契约的问题，并新增默认关闭的店铺级 AI 自动回复。部署级轮询器只为已启用店铺创建去重的增量消息同步任务；新链路在同步后写入幂等运行记录并投递独立 Redis 队列，由租户隔离 Worker 处理。仅最新、尚未人工回复、满足订单上下文和每小时限额的低风险文本可外发，退款赔付等敏感输入与模型承诺输出均转人工。队列、限流、AI 或平台发送失败全部 fail closed、留痕且不自动重试。Admin 提供敏感操作二次确认、只读权限保护和最近运行状态。

该能力不会随代码部署自动启用：Admin 页面中的消息同步、自动回复总开关和店铺策略均默认关闭，保存后动态生效。真实平台上线仍依赖对应 Provider 已验证的消息收取/发送契约、合法店铺授权、AI/Redis 可用性与人工验收；未验证平台继续保持不可用。

同日完成多实例与崩溃恢复加固：Redis 改为 ready/processing 可靠消费并由数据库 pending 扫描补发，自动回复运行使用可续租执行租约；生成阶段可安全恢复，发送阶段结果未知一律转人工。消息同步、人工回复与自动发送共享会话锁并在外发前最终复核；PostgreSQL 新增平台消息、外部会话和单店在途同步唯一约束及热查询复合索引。Admin 切店请求按序隔离，加载失败清空并禁用旧表单，远程店铺搜索采用分页与防抖。

生产验收前进一步收紧发送与运维边界：平台发送幂等租约长于平台超时并持续续期，平台成功且本地消息已落库时，即使幂等完成标记失败也只按 `clientMessageId` 重放本地消息，不再产生可重发窗口。自动回复可用状态改为 Redis、客服消息同步 Worker、轮询调度器和自动回复消费者整链路探活，`/health` 增加 ready/processing 队列与进程状态。`sending` 租约过期会原子转人工并写入统一失败中心；最近运行记录返回截断错误说明。PostgreSQL 去重迁移同时保护 `sent_message_id` 引用。Admin 运行设置加载失败时保持禁用，显式重试成功后才允许保存。
